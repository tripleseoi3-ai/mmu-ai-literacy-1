# 인터뷰 → 골 → SDD → TDD

요구사항이 말로만 오간 뒤 곧장 코드로 넘어가는 것을 막기 위한 워크플로다.
네 단계를 **순서대로** 진행하고, 각 단계는 **파일 하나**와 **사용자 승인**을 남긴다.

## 핵심 규칙 (전 단계 공통)

1. **단계를 건너뛰지 않는다.** 사용자가 "바로 코드 짜줘"라고 해도, 최소한 골 한 줄과 완료 조건은 확정하고 넘어간다.
2. **승인 없이 다음 단계로 가지 않는다.** 각 단계 끝에서 산출물을 보여주고 "이대로 진행할까요?"를 묻는다.
3. **모든 요구사항에는 ID가 붙는다.** `REQ-001` 형식. 이 ID가 명세 → 테스트 → 커밋까지 따라간다.
4. **추적성이 끊기면 미완성이다.** 테스트에 매핑되지 않은 REQ, REQ에 매핑되지 않은 테스트는 둘 다 결함으로 본다.
5. **모른다고 말한다.** 사용자가 답하지 않은 것을 추측으로 채우지 않는다. `미결정` 목록에 남기고 표시한다.

## 산출물 위치

```
docs/specs/<YYYY-MM-DD>-<슬러그>/
  01-interview.md      인터뷰 원문과 요약
  02-goal.md           골, 성공 지표, 비목표, 완료 조건
  03-spec.md           SDD 본문 (REQ-001 …)
  04-traceability.md   REQ ↔ 테스트 ↔ 커밋 대응표
```

슬러그는 영문 kebab-case (예: `2026-09-05-attendance-export`).
디렉터리는 1단계 시작할 때 만든다.

## 진행 절차

### 0. 시작 지점 확인

먼저 `docs/specs/` 를 훑어 **이미 진행 중인 건이 있는지** 본다.
- 있으면: 어디까지 됐는지 알리고 그 다음 단계부터 이어간다.
- 없으면: 1단계부터 시작한다.
- 사용자가 "SDD부터" 처럼 특정 단계를 지목하면 앞 단계 산출물을 사용자에게 받아서 채운 뒤 진행한다.

### 1. INTERVIEW — 무엇을, 왜, 누구를 위해

`references/interview.md` 를 읽고 진행한다.
- 한 번에 **3~5개**씩만 묻는다. 목록을 쏟아붓지 않는다.
- 코드/파일을 읽어서 알 수 있는 것은 **묻지 말고 직접 확인**한다.
- 답을 `01-interview.md`에 원문 그대로 기록한다. 요약은 그 아래 따로.
- 종료 조건: 성공 기준·범위 밖·제약 세 가지가 모두 채워졌을 때.

### 2. GOAL — 무엇이 되면 끝인가

`references/goal.md` 를 읽고 진행한다.
- 골은 **측정 가능한 한 문장**. "좋아진다"가 아니라 "무엇이 몇으로".
- 비목표(Non-goals)를 반드시 적는다. 범위 방어선이다.
- 완료 조건(DoD)은 체크박스로. 각 항목은 사람이 확인 가능해야 한다.
- 산출물: `02-goal.md`. → **승인 게이트**

### 3. SDD — 어떻게 동작하는가

`references/sdd.md` 를 읽고 진행한다.
- 요구사항마다 `REQ-001` 부여. 각 REQ는 **관찰 가능한 동작** 하나만 서술.
- 시나리오는 Given / When / Then 으로.
- 에러·경계 조건을 정상 흐름과 같은 비중으로 적는다.
- 결정하지 못한 것은 `미결정` 절에 남기고 사용자에게 묻는다.
- 산출물: `03-spec.md`. → **승인 게이트. 여기까지 승인 전에는 구현 코드를 쓰지 않는다.**

### 4. TDD — 테스트가 먼저

`references/tdd.md` 를 읽고 진행한다.
- REQ 하나씩. RED(실패하는 테스트) → GREEN(최소 구현) → REFACTOR.
- **실패를 눈으로 확인하기 전에는 구현 코드를 쓰지 않는다.** 테스트를 돌려 실패 출력을 보여준다.
- GREEN마다 커밋. 커밋 메시지 첫 줄에 REQ ID를 넣는다: `REQ-003: 결석 3회 초과 시 경고 표시`
- 통과시키려고 테스트를 약화시키지 않는다. 명세가 틀렸다면 3단계로 돌아가 명세를 고친다.
- `04-traceability.md` 를 매 REQ 완료 시 갱신한다.

## 마무리

전 REQ가 GREEN이 되면:
1. 전체 테스트를 한 번 더 돌려 결과를 그대로 보고한다 (실패가 있으면 숨기지 않는다).
2. `02-goal.md`의 DoD 체크박스를 실제 확인한 것만 체크한다.
3. 추적성 표에 빈칸이 있으면 남은 항목을 명시한다.
4. 미결정 사항이 남아 있으면 목록으로 다시 보여준다.

## 하지 말 것

- 인터뷰 없이 요구사항을 상상해서 채우기
- 승인 전에 구현 파일 만들기
- REQ 없이 "그 김에" 기능 추가하기
- 테스트를 나중에 몰아서 쓰기
- DoD를 확인하지 않고 체크하기
